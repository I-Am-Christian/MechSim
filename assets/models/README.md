# Pilot Operations — implementation and asset import plan

## Current implementation (v13)
- `mercenary-combat.js`: `makePilot()` creates a 1.8 m-scale infantry model and persistent health/ammo state. `togglePilot()` uses a collision-safe dismount location, parks the original chassis, and requires proximity to a living friendly chassis before boarding. `pilotStep()` handles movement, sprint, carbine/reload and damage; `pilotCamera()` handles first/third person and ADS. Pilot hitboxes use the fallback model, even if a visual replacement is loaded. Pilot health is mission-local; the pilot is excluded from chassis save settlement.
- H: dismount/board; WASD: move; Shift: sprint; LMB: fire; RMB: aim; R: reload; L: light; V: camera. The existing E escape capsule remains separate.
- `frontier-extensions.js`: after landing, initialize optional integrations sequentially with a 1.2 s gap; load GLTFLoader/Meshopt/KTX2 once, then load the pilot model when needed. `loadPilot(p)` prefers a custom `assets/models/pilot.glb`, then parses the locally bundled `pilot-data.js` base64 GLB. Normalize model to 1.8 m, center its feet, attach to pilot root, hide procedural visual, use AnimationMixer to drive its walking clip. If loading fails, the procedural pilot remains playable.
- `mercenary.html` and `mercenary.js`: H button, current mode HUD, credits and versioned module imports.
- Startup: smaller terrain textures (384² desktop versus 768²), lower base render resolution, no shadow rendering during descent, first enemies staggered by 0.22 s after landing, environment reflection generation delayed until combat begins, optional dependencies loaded sequentially.

## Next asset import steps
1. Download the CC0 [Quaternius Animated Mech Pack](https://quaternius.com/packs/animatedmech.html) and [Ultimate Space Kit](https://quaternius.com/packs/ultimatespacekit.html); keep the license included with each download. Download [Poly Haven Namaqualand Boulder 05](https://polyhaven.com/a/namaqualand_boulder_05) in glTF/1K or a lower LOD if offered. These assets are not yet bundled.
2. In Blender, normalize Y-up export, origin at the feet or base, apply scale, preserve arm/leg skeletons. Export GLB with embedded textures. Use 1K textures, a low-poly LOD, and named joints `arm_left`, `arm_right`, `leg_left`, `leg_right`, `muzzle_left`, `muzzle_right` where appropriate. Do not replace existing damage hitboxes or weapon transform logic until each joint is mapped and tested.
3. Place the files at `assets/models/mechs/<chassis-id>.glb`, `assets/models/pilot.glb`, and `assets/models/environment/rock.glb`. The pilot path already works. Mech and rock paths are planned, not automatically loaded today.
4. Extend `FrontierExtensions.initModels()` to cache templates by URL. For animated skeletons use SkeletonUtils.clone, per-unit AnimationMixer, and a chassis-specific socket mapping. Attach visual model to existing unit root and retain damage meshes and collision radius. Disable procedural visible meshes only when a replacement is validated. Do not share an AnimationMixer across units.
5. For rocks, instance shared geometry/material, preserve each original obstacle radius/height, and use low LOD beyond 50–70 m. For large models run glTF Transform meshopt compression, simplify geometry, and convert suitable textures to KTX2. Test loading on low/high presets, collision, damage, muzzle positions and FPS before changing defaults.
6. License register: record original URL, creator, license and changes in this file. Only include assets approved for redistribution. CC0 preferred; CC BY needs attribution.
